# 剧透分级（粗略但可执行）

目的：把「剧透」从二元（越界/没越界）拆成**进度轴 × 伤害等级**两维。
进度轴回答「该不该说」，等级回答「说了有多糟」。两维要分开看：
给第二章玩家的答案里出现「下城区」是越界，但也就是个地名；出现「夜之歌是谁」才是真出血。

## 1. 两条轴

- 进度轴（已有）：`spoiler_axis` = act / chapter / ability / none，
  记在每个游戏的注册表里；本轮用户进度之上的内容即「越界」。
- 伤害等级（本文）：L1 / L2 / L3，记在剧透词表里，一个词一个等级。

判定顺序：先看是否越界（进度之上），再看命中的词是几级。没越界就不算剧透，
哪怕内容再劲爆——用户已经玩到了。

## 2. 等级定义

L1 轻度 / 低价值
- 是什么：地名、区域名、NPC 名、道具名、系统机制的存在性、
  「后期还有一张图」这类范围提示。
- 代价：几乎不损体验，甚至帮用户规划（提前知道有洗点、有隐藏图）。
- 例：下城区、利文顿、月出之塔、大陵墓、莎尔的试炼、「这游戏后期能洗点」。

L2 中度 / 有价值信息
- 是什么：具体解法与步骤、任务链怎么推进、触发条件、
  关键装备/构筑搭配、Boss 弱点与阶段机制、某支线可救/必死这类结论。
- 代价：替用户把「发现与推演」的过程拿走了，但故事本身没被拆穿。
- 例：「先自己打完叛徒领主再去找她，她就不会死」、
  「潮湿+闪电让伤害翻倍」、「这个 Boss 弱火」、某装备具体数值。

L3 重度 / 破坏体验
- 是什么：反转与身份揭晓、核心谜底、重大且不可逆的抉择及其后果、
  角色命运（谁死谁活）、结局走向、最终 Boss 的真相。
- 代价：用户被剧透的部分再也拿不回来，等于替他把故事读完了。
- 例：夜之歌的身份、君主与主脑的真实关系、最终抉择的两种结局、
  某角色的死亡宿命、世界观核心谎言的揭穿。

一句话记忆法：**L1 是地图，L2 是攻略，L3 是谜底。**

## 3. 处置矩阵

| 等级 | 越界时怎么做 | 线上审计 | 评测判定 |
|---|---|---|---|
| L1 | 可以直接提，不必追问进度 | 只记录，不计失败 | 不判失败 |
| L2 | 默认不给：占位提示「等你到那儿再说」，用户明确要才给 | 记为 warning | 超过 `max_level` 即失败 |
| L3 | 硬上界，一律占位，不给名字不给结果 | 记为 failure，优先人工抽检 | 超过 `max_level` 即失败 |

「等同级」的边界：用户主动报进度、主动要剧透、或明确说已通关 → 上界按用户给的走，
等级只在「没被授权」时用于判定。

## 4. 工程落点

- 词表：`api_server.SPOILER_TERMS[game] = [(term, act, level), ...]`
  （`scripts/analysis/turns_report.py`、`scripts/eval/agent_behavior.py` 都吃这份）。
- 查询：`spoiler_hits(game, answer) -> [{term, act, level}]`；
  超阈筛选：`spoiler_over(hits, max_level)`。
- 线上观测：`turn_record` 把命中写进 `spoiler_hits`（每条带 `level`），
  最坏等级 ≥3 时额外打 `spoiler_worst`；`turns_report.py --spoilers`
  按等级展示，日报里 L3 单列一栏。
- 历史数据注意：2026-11-15 之前落盘的 `spoiler_hits` 没有 `level` 字段，
  读取处一律按 `h.get("level", 1)` 兜底，所以老记录里的「巴尔」会显示成 L1
  （当时词表还没分级），不要拿它当等级结论。
- 评测：`scripts/eval/behavior_cases.jsonl` 每例给 `max_level`（该轮允许的最高等级），
  默认 1（因为用例都锚在用户报过的进度上）。

## 5. 已知局限（别把它当完整判定）

1. **词表只能抓术语出现**，抓不到「用不带术语的措辞把 L3 讲出来」。
   等级是「关键词泄露」的上界估计，不是语义判定。
2. 一个词在不同语境下等级会变（「夜之歌」只报名字 = L1；说出她是谁 = L3），
   词表按「最坏情况」标级，会偏严。
3. 目前只有 BG3 有词表；空洞骑士用 ability 轴、缺氧/怪猎是 none，
   要做需要 axis-aware 的词表（P1）。
4. 语义级判定得靠 LLM 裁判（`scripts/eval/ragas_eval.py` 已有裁判通道），
   在词表审计之后接，先用词表把明显越界捞出来。

## 6. 与事故记录的关系

`docs/ROUTING_MISROUTE_2026-11-15.md` 里「第二章泄露下城区」属于 **L1 越界**：
按本文口径不算严重，记录它的意义是暴露「兜底路径没有任何进度约束」这个机制问题，
而不是这条内容本身有多毒。同一次事故里真正严重的是伪造来源引用（见该文档 §2）。
