## I-25 流式等待期全程静默，移动网络下断连 → 前端报「网络错误」【P1】

**现象**（2026-11-25 11:56:40，IP 223.104.79.66，iPhone）：

- 11:56:15 `OPTIONS /api/ask/stream` 200，随即进入 agent 工具循环；
- 11:56:15 → 11:56:37 连续 7 次 `POST api.deepseek.com` 全部 200 OK；
- 11:56:40 `WARNING 客户端断开连接`，同一毫秒 access log 记录 `POST /api/ask/stream 200 0`
  ——整个响应体 0 字节；
- 前端 `catch` 分支渲染「网络错误，无法连接到助手服务器」。

**根因**（三层，分开修）：

1. 传输层：SSE 在首 token 前不发任何字节，实测静默可达 65s（elapsed max），中间设备/浏览器把长静默连接判死。
2. 协议层：`multi_agent.ask_stream` 只在 `AIMessageChunk.content` 非空时 yield token；
   工具调用阶段 content 为空（只有 `tool_call_chunks`），所以工具循环全程无事件。
3. 前端：loading 文案静态「思考中…」，断流时 `catch` 覆盖已有内容且无重试入口。

**附带发现（服务器侧待修）**：

- 断连分支 `except (ConnectionResetError, ConnectionAbortedError)` 没有 `quota.refund()`，
  而超时分支有 → 网络原因没拿到答案也扣 1 次额度。
- 断连轮次 `route` 落库为 null、`tokens_in=0`，统计上与正常轮并存无法区分。
- `turns` 无 `first_token_ms`，「静默期」只能靠 elapsed 间接推断。

**方案**：[`STREAM_UX_PLAN.md`](STREAM_UX_PLAN.md)（L0 心跳 / L1 计时文案 / L2 真工具事件 / L3 断流恢复 / L4 断流记账）。

**验收**：`stream_chunks=0` 轮次归零、`first_token_ms` p90 有数、iPhone 移动网络下工具多轮问题不再弹网络错误。

## I-27 建库分页器不认 refetch 的 `---` 页面分隔，页面被切碎或整库塌成一页【P0，实测】

`refetch_wiki.py` 的输出里，页面之间用一行 `---` 分隔，**行数恰好等于文件头写的「总页数」**：

| 文件 | 总页数 | `^---$` 行数 | `^## ` 标题行数 |
|---|---|---|---|
| `games/terraria/data/wiki_data_zh.md` | 3031 | 3031 | 16777 |
| `games/silksong/data/wiki_data.md` | 79 | 79 | 193 |
| `games/mhw/data/wiki_data.md` | — | 有 | 18（正文用 `# 页面名`） |

而两个建库入口的分页逻辑都**没有用这个分隔**：
`mac_build.load_wiki_documents` 按 `# 文档：` / `## ` / `# ` 三种正则切，
`ingest_game.py` 同理。页内小节也叫 `##`，于是每个小节都被当成一个独立页面。

**后果分三档，越往后越严重：**

1. **terraria（切碎）**：31,248 块 / 7,347 个 title / 3,031 个页面。
   「制作」4322 块、「历史」4255、「花絮」1979、「备注」1814、「小贴士」1388，
   通用小节名合计占 **50.8%**。
   单页实测：`## 克苏鲁之眼` 原文 **5,263 字、12 个页内小节**，建库后只产出
   **1 个 344 字的块**（其余被切成 `召唤和生成`/`行为`/`后果`/`备注`/… 12 个碎片，
   title 丢失页面归属）。
2. **silksong（切碎 + 覆盖不足）**：339 块 / 129 个 title / 79 个页面。
3. **mhw（整库塌成一页）**：1,863 块，**title 只有 1 个值 `MHWilds`**。
   第一块内容是 `Redirect to: Monster Hunter Wilds ---`（文件头）。
   即整个文件被当成一页塞进 splitter，1,114KB 正文全被切成块且共用一个 title，
   引用来源永远是「MHWilds」，无法区分。

**检索实测（真实路径，`k=4`）**：

| 查询 | top-4 title | 结论 |
|---|---|---|
| terraria「克苏鲁之眼怎么召唤」 | Demon's Eye / Eye of the Golem / Face Monster / Lunatic Cultist | MISS，页面本身没进 |
| terraria「天界塔怎么打」 | Celestial Pillars | PASS |
| silksong「Silk Soar ability」 | Grand Mother Silk / Lore / Usage | MISS（库里也确实没有 Silk Soar） |
| mhw「大剑怎么玩」 | MHWilds ×4 | 判定无意义（title 全同） |

**不是 embedding 的问题**：拿「克苏鲁之眼」页块正文反查，能把自己召回（距离 4.045 排第一）。
问题在分块与 title 归属。

**修法**（Mac 侧，`scripts/tool/mac_build.py` + `scripts/tool/ingest_game.py`，两个入口都要改）：

1. 分页前先按 `(?m)^---\s*$` 切页；
2. 页内再按 `##` 切小节，**小节块的 title 必须继承页面名**，小节名另存 `section`；
3. mhw 这类 `# 页面名` + `---` 的格式走同一条路（先按 `---` 切，再按 `#` 取页名）。

**契约测试**：`tests/test_wiki_page_split.py::test_refetch_格式按页面分页而不是按小节分页`
当前 **xfail**（这就是问题存在的证明），修好后 XPASS，届时删标记。

**验收口径**：terraria 重建后块数应接近「页数 × 2–6」而不是 ×10；抽 20 页比对
「title 与正文是否对题」；`retrieval_smoke.py --game terraria` 全 PASS。

## I-28 中文块覆盖极低 + en/zh 双路按语言顺序拼接【P1】

**数据面**（各库 `language` 分布）：

| 库 | 总块 | zh 块 | zh 占比 |
|---|---|---|---|
| terraria | 31,248 | 23,127 | 74% |

| oni | 2,120 | 274 | 13% |
| va11halla | 320 | 69 | 22% |
| silksong / cyberpunk2077 / mhw / baldurs_gate3 | — | 0 | 0%（无中文源） |

HK 只有 47 个中文块，等于中文提问基本靠跨语言 embedding 去匹配英文块。

**检索面**：`tools.search_knowledge_base` 的双路是

```python
en_docs = vs.similarity_search(..., filter={"language": "en"})
zh_docs = vs.similarity_search(..., filter={"language": "zh"})
docs = en_docs + zh_docs          # ← 按语言顺序拼接，不按分数
```

`k=4` 时前 4 条基本全是英文块，中文块即使更相关也排在后面被截掉。

**实测**：HK「螳螂爪怎么获得」top-3 = Longnail / The Collector / Collector，
而库里**确实有 `Mantis Claw` 页面**（`grep title` 能查到），只是没被召回——
Longnail 也是护符，跨语言语义更近，中文块又只有 2.4% 撑不住。

**修法分两条，性质不同**：
- 数据：给 HK / ONI / VA11 补中文 wiki（采集侧，Mac）。
- 检索：双路合并改为按相似度分数排序（`similarity_search_with_score`，FAISS 距离越小越近）。
  **这条属于主检索链路，改动前要先讲方案与影响面、由用户拍板**，不自行改。
