# 路由误判分析（来自线上 turns 记录）

> 数据源：`data/turns/2026-11-14.jsonl`、`2026-11-15.jsonl`（用户真实使用）。
> 用户反馈：「错误的进入了游戏识别环节」。以下是复现和定位。

## 现象：会话中段被弹菜单 / 掉兜底

11-14 的链条（BG3 第二章停尸房）：

| # | 问题 | 路由 | 说明 |
|---|------|------|------|
| 1 | BG3 停尸房侧面的门要30才能打开怎么办 | agent/bg3 | 正常 |
| 2 | 第二章…全是毒云的停尸房… | agent/bg3 | 正常 |
| 3 | 怎么地下还有一堆软泥怪！这是什么地方 | agent/bg3 | 正常 |
| 4 | …你说的地板开裂**在哪里**啊 | fallback | 掉兜底 |
| 5 | 但是我飞下去没有办法回来了 | menu | **弹游戏列表** |
| 6 | `BG3` | agent/bg3 | 用户被迫重报游戏 |
| 7 | 在停尸房最里面的实验室里有一个控制杆 | agent/bg3 | 正常 |
| 8 | 关于那个空壳铠甲你再讲讲他**在哪里** 怎么去 | fallback | 又掉兜底 |
| 9 | 主厅？ | menu | **又弹菜单** |
| 10 | `BG3` | agent/bg3 | 再重报 |
| 11 | 我找到路了，他从大陵寝那边有一个不详的裂隙 | agent/bg3 | 正常 |

11-15 同型：`明莎拉这个**职业**怎么说` → fallback；下一轮 `我选的好像是单手武器+盾牌`
→ menu → 用户输 `bg3` 才回来。

## 根因

1. **`graph._is_unknown_game_query()` 把泛游戏用语当成「在问未知游戏」的证据。**
   它的词表是 `攻略 / boss / 怎么打 / 如何获得 / 在哪里 / 装备 / 技能 / 职业 / 等级 / 通关`——
   这些恰恰是正常追问最高频的词。只要句子里带「在哪里」又不含已知游戏名，就被判成
   「未知游戏」。
2. **`multi_agent._game_from_history()` 遇到上面的判定就 `return None`，把 last_game 清空。**
   于是下一轮再问「主厅？」时既推不出游戏、又不算未知游戏，走到
   `detect_game_node` 最后的 else → 弹菜单。
3. **菜单的适用面过宽。** menu 本该只服务「新会话 / 换游戏」，现在任何「推不出游戏且不像
   未知游戏」的问题都会弹菜单，会话中段只要断一次上下文就掉进去。

顺手发现的第四点：**单字信号误判**。`game_registry` 里 oni 的 signals 含 `"电"`、`"热"`，
11-15 的「水电工怎么玩」被 conf=1.0 判到缺氧，而当时会话在聊 BG3。

## 建议改法（均不碰检索与提示词分层）

- A. `_is_unknown_game_query` 的泛用语只用于「要不要走兜底作答」，
  不再作为「中断上下文」的依据；另加 `_names_external_game(q)` 判断是否明确指名外部游戏
  （用 `_KNOWN_EXTERNAL_GAMES`）。
- B. `_game_from_history` 只在 `is_switch_query(q)` 或 `_names_external_game(q)` 时中断。
- C. `detect_game_node` 兜底：`history` 非空但推不出游戏 → 走 `__llm_fallback__`
  （LLM 带着历史作答），menu 只留给空历史。
- D. `game_registry` 的 oni signals 去掉单字 `电`、`热`，换成 `发电`/`电力`/`散热`/`温度管理`
  这类词（"温度" 也偏宽，建议只在与其他词共现时计分）。

验收：
- 用上表 11-14 的原始历史重放，第 4/5/8/9 轮应该分别走 agent/bg3（不再 fallback/menu）。
- 新会话里问「空洞骑士的螳螂爪在哪」仍正常；`空洞骑士` 后接 `换个游戏` 仍弹菜单。
- 补 3 个单测：会话中段短追问不弹菜单、含「在哪里」不中断上下文、外部游戏名仍能中断。

## 其他数据里看到的问题

1. **上下文膨胀**：单轮 `tokens_in` 从 7k 一路涨到 **128,916**（11-15 末几轮），
   单轮 25–28s。前端把全部历史都发上来，服务端没做轮数/字符预算裁剪。
2. **剧透仍在漏**：11-14 第 2 轮回答里出现「下城区」「Bhaal」（act 3），用户当时在第 2 章；
   `spoiler_hits` 已如实记录。属 Mac 侧 P0-1。
3. **中文专名不识别**：`明莎拉`（明萨拉/Minthara）不认识，`哨兵盾牌`、`残响机制`、
   `至圣斩` 只能靠 LLM 常识 —— 就是 glossary（4238 条）还没接线（P2-1）的症状。

## 已落地的观测（服务器侧）

turn 记录新增 `history_msgs`、`hist_game` 两列：直接看出这轮路由器能从 history 推出哪款游戏。
下次再出现弹菜单，一眼能分清是「history 没带/被清空」还是「信号缺失」。
